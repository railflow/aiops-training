This page is the file-by-file guide to [`day-12-understanding-dependencies/`](https://github.com/railflow/aiops-training/tree/main/day-12-understanding-dependencies) in the aiops-training repo. The lesson text itself is on the course site; this page only covers the files. Topic of the day: What a dependency is, why three tiny hello apps drag in hundreds of packages, what to commit, why cold CI is slow and risky, and how baking dependencies into images fixes it.

Homework for this day is in [`day-12-understanding-dependencies/homework.md`](https://github.com/railflow/aiops-training/blob/main/day-12-understanding-dependencies/homework.md) and is repeated at the bottom of this page.

## What is in the folder

24 files. Paths below are relative to the repo root unless noted.

### day-12-understanding-dependencies/deps/.forgejo/

| File | What it is | How the lesson uses it |
|---|---|---|
| `deps/.forgejo/workflows/deps-baked.yaml` | The job runs inside a builder image that already contains node_modules (see node-hello/Dockerfile.builder). Build and push the builder image first (lesson), then this job has nothing to download. | `cp deps/.forgejo/workflows/deps-baked.yaml .forgejo/workflows/` |
| `deps/.forgejo/workflows/deps-cache.yaml` | Same jobs with a runner-side cache. Cache keys come from the lockfile hash, so a changed lockfile means a cache miss. Cache support depends on your Forgejo Runner version; see the lesson. | `cp deps/.forgejo/workflows/deps-cache.yaml .forgejo/workflows/` |
| `deps/.forgejo/workflows/deps-cold.yaml` | Cold cache on purpose: every run starts from an empty job container and downloads everything. Copy to .forgejo/workflows/ in your hello-apps repo (with the three deps/ folders at its root). | `cp deps/.forgejo/workflows/deps-cold.yaml .forgejo/workflows/` |

## How to run it

Run commands from the repo root (`~/aiops-training`) unless a line starts with a `cd`. Text after `#` is what the line is expected to show.

```bash
cd day-12-understanding-dependencies/deps
wc -l node-hello/package.json python-hello/requirements.txt java-maven/pom.xml
cat node-hello/index.js
```

```powershell
cd day-12-understanding-dependencies/deps
node node-hello\index.js
python python-hello\hello.py
New-Item -ItemType Directory -Force $env:TEMP\jout | Out-Null
javac -d $env:TEMP\jout java-maven\src\main\java\hello\Main.java
```

```bash
cd day-12-understanding-dependencies/deps
node node-hello/index.js
python3 python-hello/hello.py
mkdir -p /tmp/jout && javac -d /tmp/jout java-maven/src/main/java/hello/Main.java
```

```powershell
cd day-12-understanding-dependencies/deps/node-hello
Measure-Command { npm ci --no-audit --no-fund } | Select-Object TotalSeconds
node index.js
(Get-ChildItem node_modules -Recurse -File | Measure-Object -Property Length -Sum).Sum / 1MB
(Get-ChildItem node_modules -Directory).Count
npm ls --depth=0
```

```bash
cd day-12-understanding-dependencies/deps/node-hello
time npm ci --no-audit --no-fund
node index.js
du -sh node_modules
ls node_modules | wc -l
npm ls --depth=0
npm ls --all | wc -l
```

## Homework

Work in `~/heyjob-labs/day12/`.

### Exercise 1: Measure and record

**Do:** complete this table for all three projects: direct dependencies (count lines in the manifest), installed packages, size on disk, install time (cold), install time (warm cache).

### Exercise 2: Break a lock file

**Do:** edit `package-lock.json` (change a version number by hand), run `npm ci`, and record the error. Then restore it with `git checkout package-lock.json`. Repeat for `package.json` (change a version) and note the difference between `npm ci` and `npm install`.

### Exercise 3: Cache invalidation

**Do:** in the layered Dockerfile, edit only `index.js` and rebuild (fast), then add one dependency to `package.json` and rebuild (slow). Record both build times and which layers `docker build` reported as `CACHED`.

### Exercise 4: Find the biggest folder

**Do:** find the five largest packages inside `node_modules` and explain why they are large.

### Exercise 5: Why is the lock file not ignored?

**Do:** write five sentences explaining why `package-lock.json` is committed but `node_modules` is not. Include reproducibility, review (a lock file diff shows exactly what changed), CI speed, and the supply-chain angle.

### Exercise 6: Slow, flaky, risky

**Do:** list the three reasons from this page why a cold CI install is a problem and, for each, name the fix you tried (cache, baked image) and how well it worked in your own timings.
